# Quirq content and user journeys

Accepted homepage content — 28 September 2026.

The owner accepted this content direction as the homepage. The former preview
now lives at `/`, with the three offering journeys, real product captures and
separate calls to action. Navigation uses the canonical XO logo with **Spaces**
and **Cloud**, then **MachineSpeed** and **Resources**. Old preview URLs redirect
to `/` and the superseded homepage renderers have been deleted. Detailed
offering-page sequences below remain guidance; product onboarding is unchanged.

## The central idea

**Put AI to work across your business.**

Run your company from Claude or Codex. Launch AI employees that work around the
clock. Or bring us a business problem and build the solution with our team.

Quirq is the parent brand. XO Space, XO Cloud and MachineSpeed are three ways to
start, each with its own audience and next step. They are not three subscription
tiers or a sequence that every customer must complete.

The distinction visitors should remember:

- **XO Space:** You build and direct the work from your agent session.
- **XO Cloud:** You launch and manage AI employees on a managed platform.
- **MachineSpeed:** Our people and agents build the solution with you.

Retain the existing Trusted by section and its original eight brands. Product

### 4. Demonstrate each promise

Section heading: **See the work in action.**

Each example should show a specific task, what Quirq contributes, and the result
the user can inspect. A focused example is more useful than another feature list.

- XO Space: a real Claude or Codex session carrying out a company workflow.
  Existing project, session and sharing captures support those narrower features.
  They do not yet demonstrate the complete company-management promise.
- XO Cloud: an AI employee receiving work, running it, and producing a result.
  Current setup and usage tours can explain configuration, but should retain
  their existing labels and provenance.
- MachineSpeed: a documented business problem, the pipeline built with the
  customer, and a substantiated outcome. Use a named case only with a source;
  identify conceptual examples as examples.

Until these examples exist, use the available truthful product media and link to
the relevant walkthrough. Do not fill the gap with invented results or screens.

### 5. Close with the same three paths

Heading: **Choose where to start.**

- **Build with XO Space** → `/products`.
- **Run on XO Cloud** → `/xo`.
- **Work with MachineSpeed** → `/machinespeed`.

Avoid a cloud-only closing action that loses the developer and services paths.

## XO Space: the developer journey

Visitor intent: **“I want to run my company through the agent I already use.”**

Hero: **Your company. One agent session.**

Supporting copy: **An open-source workspace for managing your company from
Claude Code or Codex. Your projects, tools and workflows, in one place.**

Primary action: **Get XO Space** → the existing repository or local install
section. Secondary action: **Read the setup guide** → the Space docs.

Website sequence:

1. Explain the single-session promise and who it is for.
2. Show concrete company workflows supported today, once supplied by the owner.
3. Demonstrate a real session, with project context and inspectable output.
4. Explain local setup, agent accounts and connection requirements.
5. Offer installation, GitHub and documentation together.

Intended activation journey: discover XO Space → inspect the repo and setup
guide → install → connect the supported agent and tools → complete a first
company workflow → inspect the result.

This is a proposed user journey, not a claim that an onboarding wizard implements
these exact steps. Success means completing useful work, not merely opening GitHub.

Optional next path: XO Cloud when the visitor wants managed, around-the-clock
execution. Open-source use does not require buying the managed platform.

## XO Cloud: the operator journey

Visitor intent: **“I want AI employees working while I am away.”**

Hero: **AI employees. Working around the clock.**

Supporting copy: **Create, launch and manage autonomous AI employees on a managed
platform. Give them work. Follow their progress. Review the results.**

Primary action: the existing **Try on XO** control → `APP_URL`.
Secondary action: **See how it works** → the page's walkthrough.

Website sequence:

1. Define an AI employee as an agent configured to carry out ongoing work.
2. Show a supported template and the kind of work it is intended to do.
3. Explain the setup: environment, connected tools and model credentials.
4. Show how a user starts work and inspects activity and results in the actual app.
5. Explain the relevant subscriptions and trial before the signup action.

Intended activation journey: choose a use case → choose a supported template →
configure the environment and connections → launch → assign work → inspect the
first result → manage ongoing work and usage.

The app's actual controls must substantiate each step before the page presents it
as a recorded walkthrough. Do not imply every template includes scheduling,
approval controls or automatic retries unless demonstrated.

Use **24/7** for the owner-described operating model, not a measured uptime
guarantee. Keep the existing 30-day trial qualification for eligible Starter and
Pro accounts wherever trial copy appears. This content pass changes no prices.

## MachineSpeed: the business-owner journey

Visitor intent: **“I have a business problem and want a team to solve it.”**

Hero: **Your business problem. Our people and agents.**

Supporting copy: **We design, build and run agent pipelines around your business.
Work directly with our team, see progress and shape the result.**

Primary action: **Tell us what you want to solve** → the established contact
destination, `mailto:hello@quirq.ai`. Secondary action: a sourced example when one
is available.

Website sequence:

1. Explain the human-and-AI delivery team and the business outcome it works toward.
2. Show sourced examples of problems and delivered solutions.
3. Explain collaboration: define the outcome, build together, review, put to work.
4. Explain what the engagement covers and how ongoing operation is scoped.
5. Invite the visitor to describe a problem, their current tools and desired result.

Intended engagement journey: recognize a relevant problem → describe it → agree
scope and success criteria → build with the team → review the working solution →
deploy and agree how it will be operated.

Make the process feel engaging through plain language, visible progress and
customer participation. Avoid promising a delivery timeline, universal solution
or guaranteed result that the engagement has not established. “Instantly” is an
ambition for responsiveness, not a blanket project-completion promise.

MachineSpeed is a delivery service. XO Cloud Enterprise is a platform deployment
option; neither should be used as a substitute label for the other.

## Navigation and content rules

Accepted top-level labels: **Spaces · Cloud · MachineSpeed · Resources**.
Spaces and Cloud each use the canonical XO logo in place of a written XO prefix.
Keep Research and Writing within Resources. On the homepage, route the main
action to the three choices. On each offering page, prioritize that offering's
next step. Preserve existing route URLs and the authentic XO mark.

Use the owner's names consistently: **XO Space**, **XO Cloud**, **MachineSpeed**.
After the full introduction, “Space” is acceptable in supporting prose. Keep
technical identifiers such as repository names, Space IDs and API fields intact.

Write each offering in the same order: audience → outcome → how it works → proof
→ next step. Keep infrastructure detail beneath the user-facing promise.
